# Inside a MacBook Website Implementation Plan

> **For agentic workers:** Use subagent-driven-development for the independent catalog/state task, then integrate and validate the scene and interface in this session.

**Goal:** Build the approved interactive MacBook teardown website, with a reusable cinematic timeline for the later video export.

**Architecture:** A typed part catalog and pure reducer control visibility and selection. React Three Fiber renders original procedural assemblies. The HTML interface and deterministic demo timeline operate the same model.

**Tech Stack:** React, TypeScript, Vite, Three.js, React Three Fiber, Drei, Lucide icons, Vitest, Playwright for validation.

## Visual tokens

Display/body use locally bundled Manrope with geometric weight contrast; technical captions use IBM Plex Mono. The signature is the laptop itself suspended above a faint engineering datum, with a continuous assembly rail below. Keep the initial surface a usable explorer, with no marketing hero.

## Acceptance checks

1. Slider 0 and 100 yield visibly assembled and separated parts without unexpected overlap of major assemblies.
2. Selecting a part reveals its own explanation; isolate shows only it; exiting isolation restores previous filters.
3. Filtering a selected part's system clears that selection. Search is case-insensitive. Empty searches explain how to recover.
4. Reset restores all systems, initial camera, no selection, and assembled state.
5. Orbit drags do not select meshes. HTML list supports selection without a canvas pointer.
6. Demo can start and stop; normal controls restore to usable state. Reduced motion disables unsolicited interpolation.
7. At 390px and desktop widths controls do not overflow or cover the entire usable model area.
8. WebGL failure offers a readable component list; type checking, reducer tests, production build, and browser console are checked before completion.
